# Voyage UI

Дизайн-система сайта «План путешествия по Китаю».

Voyage UI предназначена для маршрутов, бронирований, расписаний и дорожных заметок. Её характер — тёплый, спокойный и собранный: интерфейс должен ощущаться как личный путеводитель, но оставаться достаточно строгим для времени рейсов, адресов и другой операционной информации.

## 1. Принципы

1. **Сначала маршрут, затем декор.** Дата, место, время и следующий шаг всегда заметнее фотографии и поясняющего текста.
2. **Тёплая функциональность.** Скругления и мягкие цвета создают дружелюбный характер, но не снижают читаемость.
3. **Один смысл — один цвет.** Цвет обозначает роль или состояние, а не используется случайно.
4. **Подробности раскрываются постепенно.** Карточка показывает главное; описание, источники и советы располагаются ниже или в раскрываемом блоке.
5. **Одинаковая информация выглядит одинаково.** Даты, рейсы, ночёвки и статусы используют одни и те же компоненты во всех разделах.
6. **Светлая и тёмная темы равноправны.** Компонент считается готовым только после проверки в обеих темах.
7. **Мобильная версия — самостоятельный интерфейс.** На узком экране компоненты перестраиваются, а не просто уменьшаются.

## 2. Источник истины

Новые компоненты должны использовать переменные `--md-sys-*`. Старые алиасы `--blue`, `--orange`, `--sky`, `--ink`, `--muted`, `--card`, `--line` оставлены для совместимости и не должны появляться в новом коде.

При конфликте правил приоритет имеют:

1. семантические токены `--md-sys-*`;
2. маршрутные токены `--friends-route` и `--couple-route`;
3. специальные токены информационных карточек;
4. локальные стили компонента.

Не добавляйте новый `hex`-цвет, если нужное назначение уже покрыто токеном.

Тёмная тема включается через `[data-theme="dark"]`. Используются те же имена токенов, поэтому компонент не должен содержать отдельную логику переключения цвета.

Основные значения:

- фон: `#1a1112`;
- основной текст: `#f1dedf`;
- вторичный текст: `#d8c2c2`;
- основной акцент: `#ffb2b5`;
- основной контейнер: `#733337`;
- третичный контейнер: `#5e421b`;
- мягкая граница: `#524344`.

### Цвета маршрутов

| Токен | Значение | Роль |
|---|---:|---|

Маршрутные цвета применяются только к линии, маркеру, легенде или компактной метке. Не окрашивайте ими большие текстовые области без проверки контраста.

### Специальные поверхности

| Токен | Значение | Роль |
|---|---:|---|
| `--location-card` | `#f6e8c9` | Фон карточки локации |
| `--location-ink` | `#281800` | Текст карточки локации |
| `--schedule-card` | `#ead5b5` | Строка расписания внутри карточки |

Эти токены используются вместе. Нельзя применять `--location-card` с обычным `--md-sys-color-on-surface`, не проверив контраст.

## 4. Типографика

Основной шрифт — `Roboto`, запасные — `Arial, sans-serif`. Иконки — `Material Symbols Rounded`.

| Стиль | Размер / интерлиньяж | Использование |
|---|---|---|
| Display Large | `57 / 64 px` | Главный заголовок страницы |
| Display Medium | `45 / 52 px` | Заголовок крупного раздела |
| Headline Large | `32 / 40 px` | Заголовок смыслового блока |
| Headline Medium | `28 / 36 px` | Заголовок карточки локации |
| Title Large | `22 / 28 px` | Значение статистики, группа задач |
| Title Medium | `16 / 24 px` | Внутренний подзаголовок |
| Body Large | `16 / 24 px` | Основной текст |
| Body Medium | `14 / 20 px` | Подсказки, расписание, таблица |
| Label Large | `14 / 20 px` | Кнопки и интерактивные подписи |
| Label Medium | `12 / 16 px` | Даты, теги, подписи метрик |

Правила:

- не используйте текст меньше `12 px` для содержательной информации;
- заголовки не пишутся капсом;
- капс допустим только для короткой служебной метки;
- время и номера рейсов выделяются насыщенностью, а не увеличением размера;
- основной текст ограничивается комфортной шириной примерно `65–75` знаков;
- на экранах до `600 px` Display Large заменяется на Display Medium, а заголовок раздела — на Headline Large.

## 5. Размеры и сетка

- Максимальная ширина контента: `1200 px`.
- Боковой отступ страницы: `16 px`; на очень узких экранах — `10 px`.
- Базовый шаг: `4 px`.
- Рекомендуемые интервалы: `4, 8, 12, 16, 20, 24, 28, 32, 48, 64, 72 px`.
- Расстояние между крупными разделами: `64–72 px`, на мобильном — `48 px`.
- Расстояние между карточками одной группы: `10–24 px` в зависимости от плотности.
- Минимальная высота интерактивного элемента: `40 px`; основная кнопка или вкладка — `44–48 px`.

Не вводите интервалы вроде `13 px`, `27 px` или `35 px`, если они не решают конкретную проблему выравнивания.

## 6. Формы

| Токен | Значение | Использование |
|---|---:|---|
| `--md-sys-shape-corner-small` | `8 px` | Небольшая метка |
| `--md-sys-shape-corner-medium` | `12 px` | Вложенная карточка, задача |
| `--md-sys-shape-corner-large` | `16 px` | Статистика, строка переезда |
| `--md-sys-shape-corner-extra-large` | `28 px` | Основная карточка и крупная секция |
| Capsule | `999 px` | Кнопка, вкладка, дата, тег |

Правило вложенности: внутренний радиус всегда меньше внешнего минимум на один уровень.

Тень по умолчанию:

```css
box-shadow: 0 1px 2px #00000026, 0 1px 3px 1px #00000012;
```

Тень используется только для плавающих или крупных отделённых поверхностей. Строки таблиц и вложенные блоки разделяются цветом или границей.

## 7. Иконки

- Набор: `Material Symbols Rounded`.
- Базовый размер: `20–22 px`.
- Иконка всегда дополняет текст, если действие нельзя однозначно понять без подписи.
- Декоративная иконка получает `aria-hidden="true"`.
- Интерактивная кнопка без текста обязана иметь `aria-label`.
- Не смешивайте emoji и Material Symbols в одном компоненте.
- Для транспорта используйте семантические имена: `flight`, `train`, `subway`, `local_taxi`, `directions_bus`, `cable_car`.

## 8. Компоненты

### 8.1 Шапка

Состав:

- логотип `.logo`;
- иконка самолёта `.logo i`;
- статус поездки `.status`;
- переключатель темы `.theme-toggle`.

Правила:

- иконка логотипа — контейнер `40 × 40 px`, радиус `14 px`;
- статус — капсула с датами, без длинного описания;
- на мобильном статус занимает отдельную строку;
- шапка не должна конкурировать с главным заголовком.

### 8.2 Переключатель маршрутов

Классы: `.switcher`, `.route-tab`, `.route-tab.active`.

- Используйте только для двух или трёх взаимоисключающих представлений.
- Активная вкладка определяется одновременно классом `.active` и визуальным контейнером.
- Высота вкладки — не менее `44 px`.
- Обязательны `role="tablist"` у группы и понятный текст у каждой вкладки.
- Не используйте цвет текста как единственный признак активности.

### 8.3 Карточка статистики

Классы: `.stat`, `.viz-card`, `.viz-icon`.

Структура:

```html
<div class="stat">
  <small>Подпись</small>
  <b>Главное значение</b>
</div>
```

- Одно значение и одна подпись на карточку.
- В группе должно быть от двух до четырёх карточек.
- Не помещайте внутрь абзацы и кнопки.

### 8.4 Карточка локации

Классы: `.road-stop`, `.road-copy`, `.road-date`, `.road-plan`, `.road-facts`, `.place-actions`.

Обязательный порядок:

1. изображение или карусель;
2. дата;
3. название;
4. описание в 1–3 предложениях;
5. теги локаций;
6. 2–3 факта;
7. полезные действия;
8. подробный план или справка.

Не помещайте PIN, PNR, номер билета, документа, подтверждения или личный телефон в публичную карточку.

### 8.5 Переход между локациями

Класс: `.road-transfer`.

- Одна строка: транспорт + направление + ключевое ограничение.
- Формат: `HSR → шаттл · прибытие к вечеру`.
- Не повторяйте полное расписание рейса — оно находится в карточке или таблице.

### 8.6 Факты

Классы: `.road-facts`, `.road-fact`.

```html
<div class="road-fact">
  <b>12:15</b>
  <small>Вылет</small>
</div>
```

- Максимум три факта в одном ряду.
- Значение располагается над подписью.
- Подпись должна объяснять единицы и контекст.

### 8.7 Кнопки и ссылки-действия

Класс: `.place-actions`.

- Основное действие использует primary.
- Вторичное действие использует secondary container.
- В карточке допускается не более двух основных действий.
- Ссылки на внешние сайты открываются с `target="_blank" rel="noopener"`.
- Текст кнопки начинается с глагола: «Открыть карту», «Проверить отель», «Почитать».

### 8.8 Список переездов

Классы: `.moves`, `.move`, `.move-icon`.

Каждая строка содержит:

1. иконку транспорта;
2. дату;
3. направление;
4. номер рейса или вид транспорта;
5. время или логистическую подсказку.

Один переезд — одна строка. Пересадочный авиамаршрут можно объединить, если он оформлен одним билетом.

### 8.9 Таблица дорожной карты

Классы: `.road-table-wrap`, `.road-table`, `.road-table-stay`, `.road-table-flight`.

Разрешённый порядок колонок:

1. дата;
2. локация;
3. что увидим;
4. время и формат;
5. ночёвка;
6. рейсы и время вылета;
7. описание и ссылки.

Правила:

- колонки «Где бронировать» в системе нет;
- если перелёта нет, пишите «Перелётов нет», не оставляйте пустую ячейку;
- рейс оформляется блоком `.flight-leg` с номером, маршрутом, вылетом и прилётом;
- несколько сегментов разделяются тонкой границей;
- таблица на мобильном сохраняет структуру и прокручивается горизонтально;
- заголовок таблицы остаётся видимым при вертикальной прокрутке;
- одна и та же ночёвка должна совпадать в таблице, карточке дня и разделе бронирований.

### 8.10 Карточка бронирования

Классы: `.booking-card`, `.booking-label`, `.booking-facts`, `.booking-note`.

Показывайте:

- название объекта;
- даты и число ночей;
- статус;
- адрес;
- время заселения и выезда;
- вместимость и тип комнаты;
- включённое питание или важное условие.

Не показывайте:

- PIN;
- PNR;
- код подтверждения;
- номер билета или документа;
- имя гостя без необходимости;
- личный номер хозяина;
- платёжные реквизиты.

### 8.11 Подсказка

Классы: `.hint`, `.notice`, `.privacy-note`.

- Фон — tertiary container.
- Текст — on-tertiary-container.
- Один блок содержит одну рекомендацию или предупреждение.
- Для критической ошибки нужен отдельный error-токен; тёплая подсказка не заменяет ошибку.

### 8.12 План подготовки

Классы: `.prep`, `.task-group`, `.tasks`, `.task`, `.deadline-chip`.

- Задачи группируются по сроку или этапу.
- Вся строка задачи кликабельна.
- Выполненная задача меняет фон и оформление текста, но остаётся читаемой.
- Срочная метка используется только при реальном дедлайне.
- Состояние хранится по стабильному `data-key`; переименование текста не должно сбрасывать прогресс.

### 8.13 Статус готовности

Классы: `.ready-card`, `.ready-top`, `.ready-count`, `.ready-progress`, `.ready-meta`.

Обязательный формат счётчика:

```text
N из M задач
выполнено
```

- Перенос перед словом «выполнено» задаётся явно через `<br>`.
- Для `.ready-count` запрещён `white-space: nowrap`.
- Процент в тексте, ширина прогресс-бара и `aria-valuenow` обновляются вместе.
- Карточка ведёт к плану подготовки и поддерживает Enter и Space.

### 8.14 Карусель

Классы: `.road-carousel`, `.road-carousel-slide`, `.carousel-dots`.

- Все изображения имеют осмысленный `alt`.
- Высота стабильна при переключении кадров.
- Активный кадр помечается `.is-active`.
- Точки имеют `aria-current` и понятные `aria-label`.
- На мобильном поддерживается свайп.
- Не загружайте более трёх изображений на локацию без необходимости.

### 8.15 Карта

Классы: `.map-card`, `.map-head`, `.map-pin`.

- Цвет маркера соответствует части маршрута.
- Popup содержит название и дату.
- При отсутствии интернета показывается текстовая замена.
- Все точки маршрута должны существовать и вне карты.

## 9. Состояния компонентов

Каждый интерактивный компонент должен иметь:

- default;
- hover;
- focus-visible;
- active/selected, если применимо;
- disabled, если действие может быть недоступно;
- checked/complete для задач.

Глобальный фокус:

```css
*:focus-visible {
  outline: 3px solid var(--md-sys-color-primary);
  outline-offset: 3px;
}
```

Не удаляйте outline без равноценной замены.

## 10. Адаптивность

Основные контрольные точки:

- `850 px`: карточки маршрута становятся одноколоночными;
- `760 px`: строки переездов и группы задач перестраиваются;
- `600 px`: уменьшается типографическая шкала заголовков;
- `540 px`: мобильная навигация, компактные отступы и карточки;
- `480 px`: факты бронирований становятся одноколоночными.

Правила мобильного поведения:

- карточка не должна требовать горизонтальной прокрутки;
- исключение — таблица, которая прокручивается внутри `.road-table-wrap`;
- кнопки в карточке растягиваются и остаются не ниже `44 px`;
- изображения не уменьшаются ниже `210 px` по высоте в карусели;
- важный текст не обрезается многоточием;
- переносы в статусах и датах проверяются на ширине `320 px`.

## 11. Доступность

- Контраст обычного текста — не ниже `4.5:1`, крупного — не ниже `3:1`.
- Информация не кодируется только цветом.
- Интерактивные области — минимум `40 × 40 px`, предпочтительно `44 × 44 px`.
- Используйте семантические `button`, `a`, `table`, `details`, `summary`, `label`.
- У декоративных изображений пустой `alt`; у содержательных — краткое описание.
- Новое окно обозначается в поведении ссылки и использует `rel="noopener"`.
- Динамический прогресс имеет `role="progressbar"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`.
- Переключатели вида используют `aria-pressed`.
- Тема не должна сбрасывать пользовательское состояние.

## 12. Контент и формат данных

### Даты

- Полная дата: `24 октября`.
- Компактный диапазон: `24–26 октября`.
- В метках допустимо: `24 окт.`.
- Год указывается в заголовке поездки или бронировании, но не повторяется в каждой строке.

### Время

- Формат: `08:35`, всегда с ведущим нулём.
- Диапазон: `08:35–12:35`.
- Если города находятся в разных часовых поясах, добавьте: «всё время местное».

### Рейс

```text
CZ3065 · 31 октября
CSX T2 → ICN T1
Вылет 08:35 · прилёт 12:35
```

### Ночёвка

```text
Улинъюань · 2 ночи
27–29 октября · рядом с East Gate
```

### Тон текста

- дружелюбный, конкретный, без канцелярита;
- короткие предложения;
- русские названия дополняются международными, когда они нужны для навигации;
- практический совет объясняет действие, а не просто сообщает факт;
- избегайте неопределённых формулировок «где-нибудь», «примерно там», «потом разберёмся» в операционных блоках.

## 13. Правила разработки

1. Сначала выберите семантический токен, затем пишите стиль.
2. Переиспользуйте существующий компонент; новый создавайте только при новом сценарии.
3. Не стилизуйте компонент через порядковый селектор вроде `:nth-child`, если порядок может измениться.
4. Не добавляйте данные через несколько конкурирующих `DOMContentLoaded`-обработчиков.
5. Данные маршрута должны иметь один источник истины, из которого строятся карточки и таблица.
6. Не используйте inline-стили, кроме координат или вычисляемого прогресса.
7. Название класса описывает роль, а не внешний вид: `.booking-card`, а не `.pink-box`.
8. Модификатор добавляется отдельным классом: `.booking-card.wide`, `.journey-stop.girls`.
9. Компонент не должен обращаться к глобальному DOM шире собственного контейнера без необходимости.
10. После изменения проверяйте светлую, тёмную, мобильную и печатную версии.

### Рекомендуемая структура класса

```html
<article class="booking-card booking-card--wide">
  <div class="booking-card__meta">...</div>
  <h3 class="booking-card__title">...</h3>
  <div class="booking-card__facts">...</div>
</article>
```

Текущие классы сохраняются для совместимости. Новые автономные компоненты рекомендуется именовать по схеме `block__element--modifier`.

## 14. Контрольный список нового компонента

- [ ] Использует только семантические цветовые токены.
- [ ] Соблюдает шкалу отступов и радиусов.
- [ ] Имеет понятную иерархию заголовка, основного и вторичного текста.
- [ ] Работает в светлой и тёмной темах.
- [ ] Проверен при ширине `320`, `540`, `850` и `1200 px`.
- [ ] Все действия доступны с клавиатуры.
- [ ] Фокус виден.
- [ ] Иконки имеют корректные `aria-hidden` или `aria-label`.
- [ ] Длинный русский текст не обрезается.
- [ ] Пустое состояние сформулировано явно.
- [ ] В публичной разметке нет секретов бронирования и персональных данных.
- [ ] Печатная версия не теряет критическую информацию.

## 15. Definition of Done

Компонент готов, когда:

1. соответствует токенам и правилам этой системы;
2. корректно работает мышью, касанием и клавиатурой;
3. выглядит целостно в обеих темах;
4. не ломается от длинных дат, адресов и названий;
5. согласован с теми же данными в других представлениях;
6. не раскрывает чувствительные данные;
7. прошёл визуальную проверку на мобильном и десктопе.
